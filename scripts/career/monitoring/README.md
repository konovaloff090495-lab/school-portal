# Профориентация ProSchools: недельный замер

Единая точка запуска — `run.py`. Она **последовательно** собирает Метрику, Google Search Console и позиции, затем read-only агрегаты воронки и формирует общий отчёт. Одновременно тяжёлые процессы не запускаются.

Актуальный объём: **только заявки всех трёх партнёров**. Считаются сохранение заявки, подтверждение её доставки в CRM и ошибки доставки. Продажи, сделки, оплаты и выручка **EasyCode, Ukids и Синергии не собираются**. Каталог `sales/` — отложенные инструменты, оркестратор их не импортирует и не запускает. Подтверждённая доставка заявки не считается продажей.

## Платные действия только явно

Без флагов выполняются чтения трафика, GSC, существующей истории позиций и воронки:

```sh
python3 /Users/dmitriikonovalov/claude/school-portal/scripts/career/monitoring/run.py --as-of 2026-11-13
```

- `--check-positions` явно разрешает **только группу 55 запросов** «Профориентация 20261106», проект 28653775, группа 78638789, существующие индексы 5/7. До запуска проверяются цена и баланс; предел 100₽. На старте Google-проверка стоила 5,50₽. Автопополнение, новые подписки и проверка всего проекта не включаются. Повтор с тем же днём не создаёт вторую платную проверку. Другие группы, глубина и общие расписания не менялись.
- `--yandex-cloud` явно разрешает сбор той же панели 55 формулировок через существующий Yandex Cloud Search API. Датированный кэш переиспользуется, повторных платных вызовов для готовых фраз нет. При 429 сбор останавливается.
- В Топвизоре Яндекс Search API временно ограничен ночными часами, поэтому дневной запуск пропускает этот движок. Яндекс измеряется отдельным Cloud-срезом, без добавления нового поисковика в общий проект.

Google: **ТОП‑10**, Topvisor, desktop, Россия 225. Яндекс: **ТОП‑100**, Cloud Search API RU, Россия 225, профиль API не объявляется идентичным desktop. Сравниваем даты внутри одного источника, а не Google против Яндекса как единую шкалу. Не найден в ТОП‑10 — не позиция 101 и не доказательство отсутствия в индексе.

Подробности и отдельные команды: [SEO README](seo/README.md), [воронка](funnel/README.md). Для всех продаж актуальное ограничение этого общего README имеет приоритет над историческими предложениями в отдельных описаниях.

## Что означает база 6 ноября

- Предпубликационная неделя Метрики/GSC: **30 октября–5 ноября**. Новые 60 страниц опубликованы 6 ноября; старые 9 статей уже существовали. `/test/` — отдельный контроль, не автоматически часть новой конверсионной воронки.
-6 ноября — неполный день запуска. Точный first-party учёт начинается с `activated_at_utc` telemetry v2, а не с полуночи. Историческую неразмеченную воронку нельзя восстановить нулями или включить в боевые показатели.
- Стартовая панель:0/55 в GoogleТОП‑10 и 0/55 в ЯндексТОП‑100. Это зафиксированная граница наблюдения; не утверждение об отсутствии сайта во всём поиске.
- GSC перед запуском вернул строки для 6 старых URL:7 кликов,276 показов,CTR2,54%. Отсутствующие строки 69‑URL выборки не заполняются нулями. В стартовом APIответе 4–5 ноября ещё неполные (`firstIncompleteDate=2026-11-04`).

В общем JSON есть блок `baseline`, ссылки на исходную базу и ограничения. Оркестратор намеренно не объявляет изменение недельных показателей доказанным эффектом нового раздела.

## Как читать результат

Метрика: визиты, посетители, просмотры внутри визитов, органика/весь трафик; отдельно новый раздел,9 старых статей и прежний тест. Уникальных посетителей разных групп и дней не суммируем.

Воронка: anonymous journey — техническое прохождение в браузере, а не человек или посетитель Метрики. Основная конверсия берётся из когортного расчёта модуля measurement: отдельные journey с заявкой среди впервые вошедших в периоде. Три выбранных партнёра не превращаются в 300%. Метрика и journey не объединяются по выдуманному идентификатору.

Данные недоступны → `null`/«нет данных». Нулевой знаменатель → нет коэффициента. Успешный пустой ответ Метрики может означать измеренный 0; отсутствие строки GSC этого не доказывает. Шаг без ответа, длительность и добровольная UX-оценка — сигналы для проверки CJM, а не автоматическое доказательство его удобства или сложности.

Приём sitemap/IndexNow не равен индексации. Google sitemap принят и скачан; поле `contents[].indexed` устарело и не используется. Прямой recrawl Яндекса 6 ноября возвращал 504 даже с production VPS; это честно сохранено отдельно от успешной передачи 60URL в IndexNow. Общий замер не повторяет запросы переобхода автоматически.


## Текущий день — только отдельно

Флаг `--include-current-day` дополнительно создаёт `weekly/<as-of>/current-day/report.md` и `.json`. Он собирает только отдельные трафик и воронку за дату as-of. Эти числа не включаются в недельное окно или его коэффициенты; второй платный SEO-съём не выполняется.

```sh
python3 /Users/dmitriikonovalov/claude/school-portal/scripts/career/monitoring/run.py --as-of 2026-11-13 --include-current-day
```

Общий отчёт показывает и серверные итоги всех боевых заявок по каждому партнёру — независимо от наличия наблюдаемого входа или показа оффера, и отдельную когортную конверсию. Поэтому заявка без клиентского события не пропадает. Кликабельность CTA, старт/вход, завершение/старт и сохранение/форма рассчитываются из агрегированных уникальных journey. Нулевой или несовместимый знаменатель даёт null. Подробности 24 шагов — в отдельном отчёте воронки.

## Показы, клики и CTR Яндекса

`seo/yandex_ctr.py` читает только URL-статистику 69 разрешённых страниц через официальный Вебмастер `query-analytics/list`: префикс нового раздела и 9 точных старых путей, с окончательной проверкой URL по whitelist. Данные API доступны за последние две недели и фильтруются по фактическим датам ответа. Скрипт включён в обычный SEO refresh; сбор только для чтения, без платных SERP-проверок.

6 ноября все 10 запросов ответили HTTP200, но даты данных оказались **23 сентября — 6 октября**. Поэтому CTR Яндекса за текущую неделю недоступен (`stale_source_dates`, клики/показы/CTR = null), а не 0. Общие показатели хоста и CTR Google вместо него не используются. При повторе 13 ноября скрипт проверит реальные даты ещё раз. [Официальная документация](https://yandex.ru/dev/webmaster/doc/ru/reference/host-query-analytics).

Трафик охватывает 69 URL, включая 9 старых статей, но заявки этой воронки относятся только к новому career-flow. Прежние embedded LeadForm и старый `/test/` в эти заявки не включаются. Нельзя делить заявки новой воронки на весь трафик 69 URL и называть это полной конверсией сайта.
