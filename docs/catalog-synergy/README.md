## Метрика108789843

Зарегистрированные цели и числовые ID: `goals.json`. Имена в интерфейсе начинаются с «Каталог · Пробные14дней» и «Каталог · Аттестат».

Для каждого оффера:

| Суффикс события | Условие |
| --- | --- |
| `banner_click` | Нажали именно на баннер, не на автоматический поп-ап |
| `form_view` | Не менее25% формы оказалось в видимой области; один раз на смонтированную форму |
| `form_start` | Первое изменение текстового поля формы; checkbox и простой фокус не считаются |
| `cta_click` | Нажали кнопку заявки или CTA выбора программы/экстерната; положение передаётся в `placement` |
| `lead_success` | `submitLead()` подтвердил успешную отправку; ошибки/невалидная форма не считаются |
| `lead_top`, `lead_middle`, `lead_bottom` | Та же успешная заявка с конкретного места в панели |

Пример: `catalog_attestat_banner_click` → `catalog_attestat_lead_success`. Общую конверсию считают по агрегатной `lead_success`. Цели трёх позиций дают разбивку: их не нужно прибавлять к агрегату второй раз. Клики и заявки — разные события; повторные клики не считаются заявками. Данные начинают накапливаться после публикации, прошлые события не восстанавливаются.

В параметры событий попадают только фиксированные `offer` и `placement`. Имя, телефон, email, текст вопроса и другие значения формы не отправляются в Метрику. Исключение в аналитике не блокирует открытие панели или заявку.

В CRM первая форма сохраняет прежний source; у следующих добавлены «· середина панели» / «· конец панели». `qualification.goal` сохраняет исходный смысл оффера. Общие формы сайта сохраняют прежние подпись кнопки, подарки и правила согласий.
